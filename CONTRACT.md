# 即梦积分管家 · 本地试用版

目标：员工只安装管理员配置好的扩展，正常使用即梦；管理者用一个 Web 页面查看余额、流水、同步状态。独立项目，不改现有视频智能体，不自动切换即梦账号，不代为生成。

运行：Node 22 内置 SQLite + HTTP，React/Vite/Semi UI。服务器只绑定 127.0.0.1:4318，本轮交付本机试用；多电脑 rollout 需要 HTTPS 地址和管理员完成分发。私密运行数据放 .local/（不入 git、不入交付压缩包）。

## API contract

- GET /api/session → {authenticated:boolean, role:'admin'|null, localPilot:true}
- POST /api/admin/login {secret:string} → HttpOnly SameSite=Strict admin cookie; secret is generated on first server start in .local/admin-secret (0600), never log it.
- POST /api/admin/logout → revoke session
- GET /api/dashboard?mode=live|demo → {mode, asOf, accounts:Account[], teams:Team[], transactions:Transaction[], identities:Identity[], installations:Installation[]}; teams and identities default to []; demo data separate from live DB, plainly marked.
- POST /api/installations {employeeName, department, role:'collector'|'admin'} → Installation (never return secret). Admin only.
- PATCH /api/installations/:id {employeeName,department,role,enabled} → Installation. Admin only.
- GET /api/installations/:id/extension.zip → same extension code + generated provision.json with endpoint and scoped installation token. Admin only. Never cache download.
- PATCH /api/accounts/:id {ownerName,ownerDepartment} → Account. Admin only. encodeURIComponent(id).
- PATCH /api/identities/:platformUserId {realName?:string|null,department?:string|null} → Identity. Admin only; encodeURIComponent(platformUserId), only IDs in the observed directory are accepted (unknown ID returns 404). At least one field is required; omitted fields stay unchanged, null clears, strings are trimmed then must be nonempty and at most 100/80 characters respectively. No nickname or ID edits.
- POST /api/sync-requests {} → SyncRequest. Admin only; fixed refresh action targeting the enabled installations at creation. Reuses an unfinished, unexpired request; returns 409 when no installations are enabled. No arbitrary commands or target IDs accepted.
- GET /api/sync-requests/:id → SyncRequest. Admin only; encodeURIComponent(id).
- GET /api/collector/commands (Bearer installation token) → {commands:[{type:'refresh',requestId,createdAt,expiresAt}],polledAt:ISO}. Claims only this installation's pending refresh targets and updates its command-poll heartbeat. Unfinished commands may be redelivered; the worker must deduplicate by requestId and use a fresh collection started at or after createdAt. No other installation's targets/results are disclosed.
- POST /api/collector/commands/:requestId/result (Bearer installation token) {status:'completed'|'partial'|'failed'|'no_open_tabs',message?:string|null} → {accepted:true,requestId,status}. Only the targeted installation can report, after claiming through a poll. The same terminal status is idempotent; a conflicting result or an expired target returns 409. Message is an allowlisted safe summary of at most 160 characters; do not send credentials, raw errors, page content or prompts. startedAt/finishedAt are server timestamps and are not accepted on input. A completed result means a fresh read and ingest acknowledgement succeeded; partial means some requested open contexts failed or were unavailable.
- POST /api/ingest (Bearer installation token) {observedAt, accounts:ObservedAccount[], transactions:ObservedTransaction[], teams?:TeamSnapshot[], status?:'ok'|'login_required'|'error', message?:string} → {accepted:true,accounts,transactions,teams}; counts report applied account/team snapshots and newly inserted transactions. Collector cannot read dashboard. Validate host, Origin, JSON sizes, IDs, finite amounts; unknown is null, no default zero. Validate against allowlisted shape and do not store raw payload. Idempotence transaction IDs, balance snapshots only move forward. No secrets, prompts, generated assets.
- GET /api/collector/status (Bearer token) → {employeeName,department,role,enabled,lastSeenAt,dashboardUrl}; extension popup status + manager entry. Admin installer role grants access to /api/admin/extension-login via POST Bearer → admin cookie. Collector cannot call it. No token in URLs.
- GET /api/health → {ok:true,version:'0.1.0'}.

Account fields: id (server derived), platformUserId, spaceId, spaceType:'personal'|'team', scope:'personal'|'team_total'|'team_member', displayName, spaceName, ownerName:string|null, ownerDepartment:string|null, balance:number|null, giftBalance:number|null, purchaseBalance:number|null, subscriptionBalance:number|null, expiresAt:string|null, lastSyncedAt ISO, source:'live'|'demo', status:'ok'|'stale'|'unknown'. ObservedAccount excludes owner edits, source and status. Identity: personal user ID; team_total space ID only (not collector ID); team_member user ID + space ID. Sum personal and team_total only; member rows must not be double counted.

Account subscription metadata: membershipPlan:string|null (max 100), billingCycle:string|null (max 50), membershipExpiresAt:ISO|null, nextRenewalAt:ISO|null, subscriptionObservedAt:ISO|null. These five fields are optional in ObservedAccount and always present in Account responses. Membership validity, the next scheduled renewal date, and credit expiresAt are independent facts: renewal may be scheduled before membership expiry and must not replace it. A personal annual membership and a team plan under the same login are stored on their respective account/space rows. Omitted metadata preserves the previous known value; explicit null records unknown. Subscription observations use their own monotonic ordering (subscriptionObservedAt when provided, otherwise the account's lastSyncedAt, which defaults to envelope observedAt); stale or equal observations cannot overwrite newer metadata. A metadata-only update preserves the last measured balance and its lastSyncedAt. Reading membership expiry must never populate or overwrite the credit expiry field. During legacy-schema migration, rows with no membership metadata start with an empty subscription watermark; rows containing metadata use their subscription observation time or conservatively fall back to the previous balance snapshot time.

Transaction fields: id (server derived from scope+eventId), eventId, accountId, chargedPlatformUserId:string|null (the Jimeng account charged, never assumed to be the human operator), occurredAt ISO, kind:'consume'|'refund'|'grant'|'expire'|'adjustment', amount:number signed, description:string, operatorName:string|null, operatorDepartment:string|null, attribution:'unconfirmed'|'matched', source:'live'|'demo'. ObservedTransaction uses platformUserId, spaceId, scope as account identity, eventId, occurredAt, kind, amount, description; unconfirmed attribution by default. Reading another person's history never proves local operator. Do not attribute based on uploader.

Legacy team history compatibility: if a transaction's chargedPlatformUserId equals its team_total/team_member wallet's spaceId, the API returns chargedPlatformUserId:null because this is a team identifier, not a person. This response normalization preserves stored history, event deduplication, amounts and other fields. The identity directory additionally excludes all exact known team space IDs from Team records and team wallet rows, even if the corresponding transaction lacks a matching wallet context. Never infer person/team type from ID length.

Installation fields: id, employeeName, department, role, enabled, createdAt, lastSeenAt:string|null, lastCommandPollAt:ISO|null, online:boolean, status:'waiting'|'ok'|'login_required'|'error'|'offline', message:string|null, accountCount:number. online means an enabled installation polled commands within the last 60 seconds; successful collection, dashboard access or ordinary status reads do not create a command heartbeat. lastSeenAt/status still describe collection separately. The collector status endpoint also returns lastCommandPollAt and online.

SyncRequest fields: id, createdAt:ISO, expiresAt:ISO, status:'waiting'|'running'|'completed'|'partial'|'failed'|'timed_out', targets:SyncTarget[]. Each SyncTarget has installationId, employeeName, department, status:'waiting'|'running'|'completed'|'partial'|'failed'|'no_open_tabs'|'timed_out', message:string|null, startedAt:ISO|null, finishedAt:ISO|null, lastCommandPollAt:ISO|null, online:boolean. The deadline is two minutes from creation, independent of device online status. Offline targets remain waiting; a poll changes the target to running, and missing results become timed_out at the deadline. A request is completed only if every target completed; mixed successes/failures are partial, all unsuccessful non-timeout results are failed, and timeout-only/no-success requests are timed_out. Target outcomes remain available for details. Jobs and results persist through server restarts; all timestamps and target scope are server-controlled. These endpoints only ask the existing plugin to refresh; they do not execute scripts, switch platform accounts, open tabs, generate content, or mutate Jimeng data.

Identity fields: platformUserId:string, nickname:string|null, realName:string|null, department:string|null, updatedAt:ISO|null. The directory deduplicates non-team_total Account.platformUserId, Team.members[].platformUserId, and Transaction.chargedPlatformUserId. Current personal or team-member display names supply nicknames; personal/member-roster observations are preferred over team_member wallet labels, with the newer observation winning within that preference. An ID-only fallback or charged-ID-only observation has nickname:null. Admin mappings are stored independently and survive later collector observations and restarts; unmapped IDs have null realName, department, updatedAt. A roster or ledger-only identity creates no wallet/installation association and does not increase accountCount. team_total uploader/representative IDs are not identities without another observed source. The same platform ID shares one mapping across personal and team spaces. Mapping identifies the account's assigned person, not the actual operator of a possibly borrowed account: it never changes Transaction.operatorName/operatorDepartment/attribution or Account.ownerName/ownerDepartment (wallet cost ownership). Collectors cannot edit mappings or supply realName/department via ingest. Filters may join by chargedPlatformUserId while explicitly labelling these as account-owner filters.

TeamSnapshot fields: spaceId (required stable platform ID), name:string (max 100), creatorPlatformUserId:string|null, creatorDisplayName:string|null (max 100), membershipPlan:string|null (max 100), membershipExpiresAt:ISO|null, totalBalance:number|null, allocatableBalance:number|null, totalSeats:integer|null, availableSeats:integer|null, membersComplete:boolean, members:TeamMember[], observedAt:ISO. TeamMember fields: platformUserId (required), displayName:string (max 100), role:'creator'|'admin'|'member'|'unknown', usedCredits:number|null, balance:number|null, joinedAt:ISO|null. All shapes are allowlisted. Numbers are finite and nonnegative; seat counts are integers. Each ingest accepts at most 100 teams and each team at most 500 distinct members, including merged partial lists; the 512 KB request-body limit still applies. Snapshot observedAt defaults to envelope observedAt and may not be later. membersComplete defaults to false; members defaults to [] for partial snapshots and is required for complete snapshots. Other fields are optional on input; omitted fields preserve previous observations and explicit null records unknown where nullable. Responses contain all fields, default unknown metadata/numbers to null, unknown member role to 'unknown', names to the platform ID when not observed, and add source:'live'|'demo'.

Teams are deduplicated by spaceId and only strictly newer snapshots update them. A partial roster merges members by platformUserId without removing known members and sets membersComplete=false. A complete newer roster replaces membership; omitted fields within a retained member preserve known values. Older/equal snapshots cannot roll back metadata, members, or coverage. Team data has its own read-only table and no create-team/invite/edit-members API. A member appearing in a roster is not evidence of a login, an installed collector, or a human operator: team-only ingest never creates Account or Installation associations and does not increase accountCount. Company credit totals still use personal/team_total Account rows only; Team.totalBalance and member balances must not be added again.

Team responses also include derived balanceObservedAt:ISO|null (output only; not accepted in ingest). It advances to the accepted snapshot's observedAt only when totalBalance was explicitly provided, including an explicit null observation. Other team updates retain the prior balance and its original balanceObservedAt, even when team.observedAt advances. No observed balance defaults to null. Legacy records with a known totalBalance but no balanceObservedAt use their pre-update observedAt as a compatibility fallback. Display balance freshness using balanceObservedAt, not the general team observedAt.

## Acceptance

1. Management page works with live/empty/demo clearly separated; useful summary, filters, account detail, ledger, employee collector setup/download.
2. Employee extension no extra login or identity form; provisioned admin setup; following active Jimeng user/space with read-only collection. No cookie export, cookie switches, prompts, assets.
3. Server persists balances/ledger; shared account/team duplicates merge, out-of-order snapshots do not regress; unknown values not zero; failed refunds distinguishable; no invented operator attribution.
4. Targeted API/security/accounting tests + browser UI verification. Verify real Jimeng adapter via current logged-in page; extension installation/lifecycle tested when Ego supports it, otherwise report exact limitation.
